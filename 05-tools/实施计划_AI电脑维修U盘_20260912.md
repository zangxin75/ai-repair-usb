## 2. 分阶段详细任务

### P0 构建环境准备（0.5 天）

**D1 上午**
- [ ] 构建机安装 Debian 12（或虚拟机），安装依赖：`live-build git curl jq squashfs-tools xorriso isolinux syslinux-efi grub-pc-bin grub-efi-amd64-bin mtools dosfstools`
- [ ] 准备 Windows 构建机（实体机或 VM），安装 Windows ADK + WinPE 加载项
- [ ] 下载 Win10/Win11 ISO，校验 SHA256
- [ ] 从网关服务方获取 tokeneff.com 测试 token
- [ ] **测试环境预制**（critic 发现 #6）：测试机 B 安装 Windows + 创建测试用本地账户 + 造测试数据（文档/图片样本）；预制一个 BitLocker 加密分区（A 机或外接移动硬盘，**记录恢复密钥到测试档案**）
- [ ] 验收：两台构建机就绪，ISO 就位，token 到手，B 机测试环境可用

### P0.5 关键技术 Spike（0.5-1 天）★ 全项目胜负手

**目标：用最便宜的方式证伪/证实三大技术假设，任何一项不过则回到方案层**

**D1 下午**（统一在**测试机 B** 上做 Spike，避免 Secure Boot MOK 登记噪音干扰验证本身 —— critic 建议 #9）
- [ ] S1. 用 Rufus/Ventoy 临时做一个**标准 Debian 12 Live U盘**（不改方案母盘）
- [ ] S2. 测试机上启动，手动安装：Node.js 20 tarball → 解压配 PATH → `npm install -g @anthropic-ai/claude-code`
- [ ] S3. **网关验证（验收口径）**：export ANTHROPIC_BASE_URL=https://tokeneff.com + token，启动 claude，**完成一次真实中文对话往返**，确认：
  - 协议兼容（/v1/messages 正常响应）
  - 鉴权通过
  - SSE 流式输出正常（观察是否中途断流——网关代理超时风险点）
- [ ] S4. **中文输入验证**：安装 fcitx5 + fcitx5-chinese-addons + fonts-noto-cjk，在 xfce4-terminal 中运行 claude，输入中文组词上屏，确认：无吞字、无光标偏移、宽字符渲染正常
  - 不通过则依次试备选：alacritty → kitty → IBus → fbterm+fcitx（纯字符）
- [ ] S5. 评估 Claude Code 原生单文件二进制（官方 install 脚本），对比 Node 方案的体积与离线打包复杂度，做出选型定论
- [ ] S6. 记录自动登录 Xfce 会话下环境变量的实际加载行为（为 welcome.sh 设计定稿）

**Go/No-Go 判定**：
- S3 + S4 全过 → 进 P1/P2
- S3 不过 → 与网关服务方排查协议兼容性；不可解决则项目暂停上报用户
- S4 不过 → 启用备选终端/输入法；全不过则回到方案层改交互形态（如 Web 终端方案）

### P1 Ventoy 打底（0.5 天）

**D2 上午**
- [ ] 量产脚本 `make-usb.sh`：Ventoy 安装到 U盘（`-g` GPT + 保留空间），数据分区 exFAT 卷标 Ventoy
- [ ] 拷入 Win10/Win11 ISO + MemTest86+ ISO
- [ ] 编写 `ventoy/ventoy.json`：默认启动项指向 AI-Repair-Live.iso（占位），菜单超时 3 秒，中文菜单
- [ ] **产物版本与回滚规范固化（critic 建议 #7/#8）**：ISO 产物命名带版本号+日期并附 SHA256（如 `AI-Repair-Live-v0.3-20260915.iso` + `.sha256`）；U盘始终**保留最近两版** Live ISO，ventoy.json 默认指向新版，新版真机翻车时从菜单手选旧版回滚（零成本）
- [ ] 测试机 A/B 验证：UEFI 启动菜单出现全部 ISO；Win11 ISO 能进安装向导（不装完，验证可启动即可）
- [ ] 测试机 A 验证 Secure Boot MOK 登记流程，截图存档（P7 说明书素材）
- [ ] 验收：双引导模式菜单正常，原版 ISO 可启动

### P2 Live 系统定制（3-5 天）

**D2 下午 - D5**
- [ ] L1. 初始化 live-build 配置仓库（git 管理，提交到项目 `05-tools/live-build-config/`）
- [ ] L2a. **apt 包清单固化** → `config/package-lists/`：git、fcitx5 全家桶、fonts-noto-cjk、全套网卡固件（firmware-linux-nonfree/realtek/iwlwifi/atheros/brcm80211/mediatek）、smartmontools、testdisk、ddrescue、ntfs-3g、exfatprogs、dislocker、chntpw、**wimtools**（提供 wimlib-imagex；注意 Debian 12 无 `wimlib` 包名）、efibootmgr、network-manager、**usbmuxd**（ipheth 为内核模块，随固件已带，无需装包）等
- [ ] L2b. **离线组件注入**（非 apt 部分）→ `config/includes.chroot/` 放文件 + `config/hooks/` 写安装钩子：Node 20 tarball 解压到 /opt/node 并配 PATH；claude-code 在构建机联网 `npm install` 后整体拷贝 node_modules（package-lock 锁版本）到 /opt/claude-code，hook 脚本建立 `claude` 命令软链
- [ ] L3. 自动登录配置：live-config 设 live 用户无密码自动登录 + 自动启动 Xfce + 全屏 xfce4-terminal
- [ ] L4. 中文环境：locales zh_CN.UTF-8 默认、fcitx5 自启动、终端字体 Noto Sans Mono CJK
- [ ] L5. welcome.sh V1（先不含持久化，P4 再加）：**内嵌简化版网络检查**（链路/DHCP/网关 curl）→ 凭证输入 → exec claude；**P3 的 R1 完成后 welcome.sh 改为调用 check-network.sh**（明确接口，避免 P2/P3 并行返工 —— critic 建议 #10）
- [ ] L6. 构建 ISO → 拷入 Ventoy U盘 → 测试机 A/B 启动验证
- [ ] L7. 迭代修复：构建-烧录-真机循环，直到验收通过
- [ ] 验收：启动后 3 秒自动进 Live → 自动登录 → 联网 → 网关通 → 自动进 Claude Code → 中文对话正常

- [ ] R9. 编写 CLAUDE.md 维修助手系统提示词（中文交流/危险确认/SOP/BitLocker 分支）
