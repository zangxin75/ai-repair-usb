# 数据抢救决策树

## 第一原则：原盘只读

任何恢复操作前先评估原盘状态，操作全部针对镜像或以只读方式进行：

- **机械盘且有异响**（咔哒/刮擦）→ 建议直接送专业数据恢复机构，老实告诉用户：
  继续通电可能刮伤盘片，家用环境没有无尘条件，自己捞 = 可能永久丢失。
- **普通场景** → 先用 `ddrescue` 做整盘/分区镜像到另一块盘，之后所有分析针对镜像做。
  镜像目标盘要有足够剩余空间（先 lsblk 确认目标盘容量），镜像写入目标盘是写操作，
  **先走 CLAUDE.md 危险操作确认流程**，让用户确认目标盘上没有要保的数据。

## 分支决策

| 症状 | 工具 | 要点 |
|------|------|------|
| 分区丢失 / 分区表损坏 | testdisk | 对镜像分析，或对原盘只读模式；先看找到的分区列表再写回 |
| 误删文件 / 误格式化 | photorec | 按文件类型捞；先只勾最要紧的一两类，小范围试捞评估成功率再全量 |
| 分区能挂载，部分文件坏 | rsync | 直接拷，坏文件跳过并记录清单，别让一个坏文件中断整场拷贝 |

## 输出要求

- **成功率预期要老实**：覆盖严重的误删、加密盘没钥匙，直接说捞不回来，
  不给虚假希望。photorec 恢复的文件会丢文件名和目录结构，提前说明。
- 捞之前检查目标盘剩余空间，不够就先告诉用户「先腾位置，别硬塞」。
- 结束时报告：捞到什么、放在哪、哪些没捞到。

## 收尾

按 verification-before-completion 技能：抽查捞出的文件实际可打开再报告完成。
原盘在确认用户数据安全落地前，不做任何写入、不格式化、不重建分区表。
