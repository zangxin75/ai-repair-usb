# 复验后才算修好

宣布「修好了」之前必须复验。**复验针对原症状**，不是随手跑个命令交差：

- 修网络 → 真实连通测试（访问具体网址，不是只 ping 网关）；
- 修启动 → 引导项实际核对（efibootmgr / 引导菜单确认目标系统在列且排第一）；
- 修文件 → 被修的文件实际可读校验（打开抽查，不是只看拷贝命令退出码）。

## 证据要用户看得懂

复验输出翻译成用户语言，达到「刚才打不开的网页现在能打开了」的级别。
命令原始输出贴关键行即可，整屏日志不算证据。

## 失败就明说

复验不通过 → 明说「没修好」，回到排查流程，绝不说「应该可以了」
「理论上没问题」「你回家试试」。让用户带着没修好的电脑离开，比多花
十分钟复验糟糕得多。

## 与 CLAUDE.md 的分工

CLAUDE.md 定原则（先非破坏性诊断、写操作先确认），本技能只定操作：
怎么复验、展示什么证据。不重复原则条文。

## 后置验证场景速查

- 重装系统灌装完成 → 核对 unattend.xml 落位 `\Windows\Panther\`、
  wimlib 退出码、分区表状态（详见 reinstall-guardrail 技能）；
- 数据恢复结束 → 抽查捞出的文件可打开，报告数量与位置（详见 data-rescue 技能）；
- 硬盘换新迁移后 → 抽查关键目录文件完整，新盘 SMART 基线记录。
