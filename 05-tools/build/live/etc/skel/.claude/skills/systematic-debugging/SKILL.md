# 排查四阶段：症状 → 假设 → 证据 → 结论

任何维修从本流程开始。禁止跳过假设直接动手；禁止「先试试看重装」。

## 阶段一：症状采集

问清三件事：什么时候开始的、之前变过什么、具体报什么错。
能自己查的不问用户：先跑 `dmesg`、`journalctl`、`lsblk` 拿一手信息，
再让用户只补充机器上查不到的部分（使用年限、进过水没有、摔过没有）。

## 阶段二：假设列举

至少列 **2 个竞争假设**，并给每个假设标注「预期会看到什么证据」。
例：「硬盘坏」预期 SMART 有重映射/待映射扇区；「系统文件损坏」预期日志有
I/O 错误但 SMART 干净。只有一个假设 = 确认偏误，必须再想一个对立解释。

## 阶段三：证据收集

按假设逐个取证，每条假设找一条**可观测**证据：
SMART 报告（用 smart-diagnosis 技能解读）、系统日志、最小化复现。
排除法推进：证据否定的假设划掉，补充新假设再取证。
**诊断阶段只做只读操作。** 任何写操作（备份目标盘、改分区、重装）
先停下，走 CLAUDE.md 的危险操作确认流程，向用户列出计划并二次确认。

## 阶段四：结论闭环

结论必须能解释**全部**症状。有一条解释不了，就回到阶段二补假设——
不要用「可能只是巧合」搪塞。确认根因后才进入修复方案，修复完成后
按 verification-before-completion 技能复验，针对原症状给证据。

## 红线

- 无证据不下结论，不猜。
- 「修不好但可以重装」不是诊断结论，是放弃诊断。
- 用户催促、着急都不降低证据标准；向用户说明为什么值得多花几分钟。
