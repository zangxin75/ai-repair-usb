## 1. 需求分析

### 1.1 产品定位

制作一个**可从 U 盘启动的 AI 电脑维修工具盘**，启动后自动驱动网卡接入 Internet、连通 tokeneff.com 网关，随后自动进入 Claude Code 中文交互界面，用户通过自然语言（中文）指挥 Claude Code 执行电脑维护、故障诊断、系统重装等任务。

### 1.2 目标用户与场景

| 用户类型 | 典型场景 | 核心诉求 |
|---------|---------|---------|
| 家庭用户 | 电脑变慢、中毒、系统崩溃自救 | 零门槛，插上就能用，中文对话 |
| 上门维修人员 | 客户现场诊断、数据备份、重装系统 | 工具齐全、诊断高效、专业可靠 |
| 装机人员 | 新机批量安装 Windows 10/11 | 快速部署、无人值守安装 |

### 1.3 功能需求

0. **网络优先（最高优先级，新增）**：启动后第一时间驱动网卡（有线/无线/USB 网卡/手机 USB 共享网络），接入 Internet，并与 tokeneff.com 网关建立连接，Claude Code 全部 AI 流量经该网关转发
1. U 盘插入电脑后可从 U 盘启动（支持 UEFI + Legacy BIOS 双模式）
2. 内置 Windows 10 / Windows 11 原版安装镜像（ISO）
3. 内置 Claude Code 及其全部运行依赖，离线可启动运行环境
4. 启动后**自动进入 Claude Code 交互界面**，无需用户手动操作
5. 支持**中文输入、中文显示、中文对话**
6. 可执行的维护任务（由 Claude Code 驱动）：
   - 硬件信息检测与故障诊断（CPU/内存/硬盘 SMART/温度）
   - 磁盘管理：分区、格式化、坏道检测、数据救援
   - BitLocker/设备加密分区的检测与解锁引导（用户提供恢复密钥后操作）
   - 系统维护：引导修复、密码重置、系统文件修复（离线挂载 Windows 分区）
   - 系统重装：引导用户选择镜像、分区方案，完成 Windows 安装
   - 数据备份：将用户数据拷贝至 U 盘或移动硬盘
7. Windows 装机流程：从镜像选择 → 分区 → 安装 → 驱动安装的全流程引导

### 1.4 非功能需求

- **易用性（V1.3 升级为最高体验原则）**：**最小心智消耗**——
  - 制作端：用户在网站上复制一条安装链接/命令，全自动完成 U盘 制作，无需理解任何技术概念
  - 使用端：能用编号选择的就不用自由对话；能帮用户选的就自动选最优方案并标注「推荐」；危险操作只保留一次确认
- **兼容性**：支持近 10 年主流 PC（UEFI 为主，兼顾 Legacy）；支持 NVMe/SATA/Intel VMD 平台
- **网络适应**：网卡驱动全覆盖 + 多级联网兜底；无网时降级为本地诊断工具
- **安全性**：不预置任何用户的 API 凭证；凭证由用户首次使用时自行配置
- **容量**：U 盘 ≥ 64GB（推荐 128GB）

## 2. 总体架构

### 2.1 架构选型决策

**关键决策点：Claude Code 的运行宿主环境选什么？**

| 方案 | 可行性 | 结论 |
|------|--------|------|
| A. Windows PE + Claude Code | WinPE 可跑 Node.js，但中文输入法、网络驱动、Node 生态在 PE 下问题多，定制成本高 | ❌ 放弃 |
| B. Linux Live 系统 + Claude Code | Node.js 原生支持，中文环境成熟，硬件检测/磁盘工具生态完整 | ✅ **采用** |
| C. 纯 DOS/UEFI Shell | 无法运行 Node.js | ❌ 放弃 |

**最终架构：Ventoy 多启动 + 定制 Debian Live（AI 维修环境） + WinPE（引导修复/驱动注入） + Windows 镜像区**

```
┌─────────────────────────────────────────────────┐
│                    U 盘 (≥64GB)                   │
├─────────────────────────────────────────────────┤
│  Ventoy 引导层 (EFI 分区, 32MB)                   │
│  ├─ UEFI 启动 / Legacy BIOS 启动                  │
│  └─ 启动菜单 → 列出所有可启动项                     │
├─────────────────────────────────────────────────┤
│  数据分区 (exFAT, 卷标 Ventoy, 剩余全部空间)        │
│  ├─ /ISO/                                        │
│  │   ├─ Win10_22H2_Chinese_x64.iso              │
│  │   ├─ Win11_24H2_Chinese_x64.iso              │
│  │   ├─ AI-Repair-Live.iso  ← 定制维修系统(默认启动) │
│  │   ├─ WinPE_x64.iso       ← 引导修复/驱动注入用   │
│  │   └─ MemTest86+.iso      ← 内存检测            │
│  ├─ /ventoy/ventoy.json  ← 默认启动/菜单配置       │
│  ├─ /config/  ← Claude Code 配置与凭证(替代persistence)│
│  ├─ /Drivers/  ← 网卡/存储(VMD)驱动包              │
│  └─ /Tools/  ← 装机辅助工具                        │
└─────────────────────────────────────────────────┘
```

**为什么用 Ventoy 而不是直接写镜像？**
- 免刻录：ISO 文件直接拷入即可启动，后续升级镜像 = 替换文件
- 多启动：一个 U 盘同时承载 Win10/Win11/维修系统/WinPE/MemTest86+
- 双引导：原生支持 UEFI + Legacy
- **配置持久化改走 exFAT 数据分区**（见 §2.2.4），不押注 Ventoy persistence 插件

### 2.2 定制 AI 维修 Live 系统（核心）

基于 **Debian 12 Live (Xfce 精简桌面)** 用 live-build 定制，构建产物为 `AI-Repair-Live.iso`：

```
开机自动流程:
BIOS/UEFI → Ventoy → (默认3秒) AI-Repair-Live.iso
    → 自动登录 (live 用户, 无密码)
    → 自动启动 Xfce + 全屏终端 (xfce4-terminal)
    → 启动欢迎脚本 welcome.sh
        ├─【第1步·挂载】挂载 Ventoy 数据分区 (mount-ventoy-data.sh → /mnt/ventoy)
        │   （必须先于凭证读取：token 存放在该分区 /config/ 下）
        ├─【第2步·网络优先】
        │   ├─ 检测有线网卡 → 自动 DHCP
        │   ├─ 检测无线网卡 → nmtui 引导连接 WiFi
        │   ├─ 无可用网卡 → 提示插入 USB 网卡或手机 USB 共享网络
        │   ├─ Internet 连通性测试 (ping/curl)
        │   └─ 网关连通性测试 (探测 API 端点，见 §2.2.1-C)
        │       ├─ 通 → 继续
        │       └─ 不通 → 中文分类诊断提示(DNS/网关故障/无网) + 重试/离线模式选择
        ├─【第3步·凭证】welcome.sh 内显式读取 /mnt/ventoy/config/auth_token
        │   并 export ANTHROPIC_BASE_URL / ANTHROPIC_AUTH_TOKEN（不依赖 profile.d 时序）；
        │   无 token 则引导用户输入(首次)并写入数据分区
        ├─【第4步】显示中文使用说明（每屏 ≤7 行，结论先行）
        ├─【第5步·主菜单】whiptail 中文菜单（§2.6.1 六选项）
        │   ├─ 选 1-5 → 以初始 prompt 启动 claude 接管对应固化流程（§2.6.5）
        │   └─ 选 6   → exec claude 自由对话
        │   （在线/离线共用同一菜单框架；离线时隐藏依赖 AI 的项 —— §2.6.4）
        └─
```

#### 2.2.1 网络与网关接入设计（最高优先级 · 新增章节）

**A. 网卡驱动全覆盖**

| 层级 | 内容 |
|------|------|
| 内核模块 | Debian 12 内核 6.1 原生驱动（覆盖绝大多数 Intel/Realtek 有线） |
| 固件包 | `firmware-linux-nonfree`、`firmware-realtek`、`firmware-iwlwifi`、`firmware-atheros`、`firmware-brcm80211`、`firmware-mediatek` 全套集成 |
| USB 网卡 | RTL8152/8153、AX88179/AX88178A（内核原生支持，作为板载网卡不识别的兜底硬件） |
| 手机共享 | 内核 `usbnet`/`rndis_host` 模块支持 Android USB 共享网络；iPhone 个人热点（`ipheth` + `usbmuxd`） |

**B. 联网兜底策略（按优先级）**
1. 有线 DHCP（最稳定，维修场景首选）
2. WiFi（nmtui 中文引导）
3. USB 网卡（U盘附件清单中建议随盘附带一个 RTL8153 USB 网卡）
4. 手机 USB 共享网络 / 手机热点（最终兜底，现场无网线无 WiFi 时使用）

**C. tokeneff.com 网关接入**

```bash
# 网关环境变量由 welcome.sh 在挂载数据分区后显式 export（见 §2.2 启动流程），
# 不再使用 /etc/profile.d 自动加载（自动登录的 Xfce 会话不一定经过 login shell，
# 且 profile.d source 时数据分区尚未挂载，token 会读到空串 —— critic 复审发现 #3/#7）
export ANTHROPIC_BASE_URL="https://tokeneff.com"   # Claude Code 全部 API 请求经网关转发
export ANTHROPIC_AUTH_TOKEN="$(cat /mnt/ventoy/config/auth_token 2>/dev/null)"  # 用户首次配置后存入U盘
```

- **连通性检查**（welcome.sh 内置，进入 Claude Code 前必须通过）：
  ```bash
  # 分级诊断: 网卡链路 → DHCP → DNS 解析 → Internet → 网关 API 端点
  check_network() {
    ip link show | grep -q "state UP"        || fail "未检测到已连接的网卡"
    ip route | grep -q default               || fail "未获取到 IP 地址(DHCP失败)"
    getent hosts tokeneff.com >/dev/null     || fail "DNS 解析失败，请检查网络"
    # 探测 API 端点而非首页（critic 复审发现 #4）：
    # 401/4xx = 网关可达、鉴权问题（通过，进入凭证步骤）；5xx/超时 = 网关故障
    code=$(curl -s -o /dev/null -w '%{http_code}' --max-time 10 \
           -X POST https://tokeneff.com/v1/messages)
    case "$code" in
      4*) : ;;                                # 可达，继续
      *)  fail "网关 tokeneff.com API 端点异常 (HTTP ${code:-超时})" ;;
    esac
  }
  ```
- **网关不通的处理**：中文提示分类故障原因 → 提供「重试 / 重新配网 / 进入离线诊断模式」三选项。**不允许跳过网关直接进入 Claude Code**（避免用户在默认端点上消耗时间排查）。

**D. 断网关降级**：无网络或网关不可达且用户选择离线模式时，welcome.sh 启动**中文菜单式本地诊断工具**（硬件检测/磁盘检测/数据备份/密码重置均可离线运行），保证 U 盘无网也有基本价值。

#### 2.2.3 Claude Code 预配置

- **网关预置**：`ANTHROPIC_BASE_URL=https://tokeneff.com` 系统级写入（见 §2.2.1-C），用户无需感知端点配置
- **系统提示词定制**（`~/.claude/CLAUDE.md` 预置）：定义"AI 电脑维修助手"角色：
  - 全程使用中文与用户交流
  - 危险操作（格式化、删分区、写盘）必须先向用户确认
  - 优先使用非破坏性诊断
  - 遇到 BitLocker 加密分区：先检测 → 引导用户从微软账户获取恢复密钥 → dislocker 解锁后再操作
  - 内置维修 SOP：诊断流程、重装流程、备份流程
- **预置维修脚本**（`/usr/local/bin/`）：
  - `check-network.sh` — 分级网络诊断（链路/DHCP/DNS/Internet/网关）
  - `mount-ventoy-data.sh` — 显式挂载 Ventoy exFAT 数据分区到 /mnt/ventoy（critic 发现 #8）
  - `disk-check.sh` — SMART/坏道检测
  - `bitlocker-unlock.sh` — BitLocker 检测+解锁向导（critic 发现 #18）
  - `win-reset-password.sh` — Windows 密码重置
  - `backup-user-data.sh` — 用户数据备份
  - `install-windows.sh` — 无人值守装机（wimlib 灌装，见 §2.3）
- **权限模型**：live 用户配置免密 sudo；Claude Code 层通过 CLAUDE.md + 脚本内置二次确认约束危险操作
- **版本更新机制**（critic 发现 #13，复审 #6 修订）：提供 U 盘内 `update-claude.sh` 脚本——联网环境下从网关/npm 源拉取新版 claude-code，**以 tar.gz 压缩包形式**存于数据分区 `/config/claude-code-latest.tar.gz`（exFAT 不支持 Unix 权限与符号链接，node_modules 树不能直接落 exFAT）；welcome.sh 挂载后解包到 Live 系统可写层再优先加载；解包失败则回退 ISO 内置版本

#### 2.2.4 配置持久化方案（critic 发现 #5 修订）

**放弃 Ventoy persistence 插件**（对标准 Debian Live 支持未经官方验证），改用确定性更高的方案：

- Ventoy 数据分区（exFAT）上建 `/config/` 目录，存放：`auth_token`、`settings.json`、`claude-code/`（可选更新版本）
- Live 系统启动后 `mount-ventoy-data.sh` 挂载该分区（exFAT 挂载是确定可行的），welcome.sh 将配置软链/拷贝至 `~/.claude/`
- **凭证存储说明（措辞修正，critic 发现 #11）**：凭证默认**明文存储于 U 盘本地** `/config/auth_token`（权限 600）；U 盘遗失 = 凭证泄露风险，说明书明确告知，并提供可选的 LUKS 加密容器方案供维修人员用户启用

### 2.3 Windows 装机链路（critic 发现 #2 重大修订）

**路径一（推荐，家庭/维修）**：Ventoy 菜单直接选 Win10/11 ISO → 走微软原版安装向导。Claude Code 事先在维修系统中给出图文指引。

**路径二（高效，装机员）无人值守装机，修订后的真实可行流程**：

```
AI 维修系统 (Linux) 阶段:
  1. mount-ventoy-data.sh 挂载数据分区，定位 /ISO/WinXX.iso
  2. 分区: parted 创建 GPT → ESP(100M,FAT32) + MSR(16M) + 主分区(NTFS)
  3. 灌装: wimlib-imagex apply install.wim <索引> → 主分区
     （ISO 无需完整解压，wimlib 可直接从 ISO 内挂载读取或先行提取 wim）
  4. 应答文件: 写入 unattend.xml 到主分区 \Windows\Panther\unattend.xml
     （OOBE 阶段应答文件的文档保证标准位置；分区根目录的 autounattend.xml
       在无安装介质在场时不可靠 —— critic 复审发现 #5，P5 实测确认 OOBE 自动跳过）
  5. 重启 → Ventoy 菜单选择 WinPE_x64.iso
WinPE 阶段:
  6. WinPE 内先 diskpart 为 ESP 分配盘符(如 S:)，再运行
     bcdboot C:\Windows /s S: /f UEFI  ← bcdboot 是 Windows/WinPE 专属工具
  7. (可选) DISM 离线注入存储/网卡驱动
  8. 重启 → 从硬盘启动 → OOBE 自动完成
```

- **验收口径明确**（critic 歧义项）：「5-8 分钟/台」指步骤 1-5（Linux 侧灌装+重启到 WinPE）耗时；完整到桌面约 15-20 分钟（含 OOBE）
- **备选方案**：若 WinPE 链路验证不顺，退回纯 Linux 手工引导（复制 `Windows\Boot\EFI` 启动文件 + 预制 BCD 模板 + efibootmgr 注册），此备选需真机实测后才可启用

**Intel VMD/RST 存储驱动应对**（critic 发现 #4，复审严重 #1 修订）：
- 制作阶段：在 Windows 构建机上用 **DISM 将 Intel RST/VMD 驱动预注入 install.wim** 后再放入 U 盘（`DISM /Mount-Image` + `/Add-Driver`），覆盖 11 代以后 Intel 平台
- **WinPE 同步注入**：WinPE_x64.iso 制作时同样用 DISM 对其 **boot.wim** 注入 RST/VMD 驱动——否则 WinPE 在 VMD 新机上看不到 NVMe 盘，bcdboot 无法执行（install.wim 里的驱动只服务于安装后的 Windows，不服务于 WinPE 自身）
- 现场应急：说明书指导「BIOS 中关闭 VMD/改 AHCI 模式」作为备选
- 驱动来源：Intel 官网 RST 驱动包，存于 `/Drivers/VMD/`

### 2.4 安全与合规设计

1. **凭证安全**：不预置任何凭证；用户 token 明文存于 U 盘本地（已告知风险），可选 LUKS 加密；网关凭证由 tokeneff.com 服务方签发管理
2. **数据安全**：所有写操作（格式化/分区/灌镜像）必须经 Claude Code 向用户二次确认；脚本内置目标盘保护校验（按设备 by-id 路径排除 U 盘自身，防误写）
3. **BitLocker 合规**：仅在用户提供恢复密钥后解锁，不绕过加密
4. **镜像合规**：Windows ISO 一律从微软官方服务器获取——手动制作用户从微软官网下载；一键制作通过 Fido 式动态解析实时获取微软官方授权链接（§2.5.3），**本项目任何环节都不分发微软字节**；产品不预装盗版激活工具；安装激活由用户自备正版密钥
5. **第三方工具审慎**：`/Tools/` 目录若收录第三方驱动工具，单独标注「可选第三方工具，用户自行取舍」（critic 发现 #17）
6. **隐私**：维修系统默认不收集任何数据；Claude Code 遥测遵循其默认政策并在说明中告知；经网关转发的对话数据的隐私政策由 tokeneff.com 网关服务方说明

## 2.5 一键制作系统（V1.3 新增）

**目标：用户在网站上复制一条安装链接/命令，粘贴执行后全自动完成 U盘 制作，全程只需一次确认。**

### 2.5.1 用户流程

```
用户打开制作网页 (如 https://tokeneff.com/usb)
  → 页面显著提示「制作将清空 U盘全部数据，请先备份」
  → 页面显示一行命令 +「复制」按钮
  → 用户插入 U盘，在自己的电脑上粘贴执行
  → 安装器自动: 探测U盘 → 列出候选盘(容量/型号)让用户选一次
  → 下载组件 → 写入 → 校验 → 「制作完成，可以拔下使用了」
```

**用户主动操作仅两步**：复制粘贴命令 + 一次选盘确认。Windows 的 UAC 提权框与杀软/SmartScreen 提示属系统预期行为（无法也不应绕过），网页 FAQ 配图预先说明，避免用户惊慌。

### 2.5.2 安装器支持端（V1.4 修订：V1 仅支持 Windows 与 Linux）

| 用户系统 | 形态 | 命令示例 |
|---------|------|---------|
| Windows（家庭用户主力，**制作场景的绝对主力端**） | PowerShell 一行命令（无需装任何软件） | `irm https://tokeneff.com/usb.ps1 \| iex` |
| Linux | 终端一行（**仅写入自产组件**，不下载 Win ISO —— Fido 为 PowerShell 实现无 bash 等价物；需要 Win ISO 的 Linux 用户按制作教程手动从微软官网下载拷入，与 macOS 砍端同一低成本决策逻辑） | `curl -sL https://tokeneff.com/usb.sh \| sudo bash` |
| ~~macOS~~ | **V1 不支持** | Ventoy 官方无 macOS 安装端（Ventoy2Disk.sh 依赖 Linux 专属工具链），自研写入器成本高（2-3 天+）且 macOS 用户占比极低；FAQ 引导 macOS 用户用 Parallels/UTM 虚拟机跑 Windows 安装器 |

- Windows 端 PowerShell 脚本覆盖 Win10/11 自带版本（5.1+），不依赖第三方工具——这是「复制链接即可制作」成立的关键
- 两端脚本共用同一套服务器 manifest（见下），行为一致

### 2.5.3 安装器行为（全自动流水线）

1. **环境自检**：管理员/root 权限检查；磁盘空间检查
2. **U盘探测**：枚举可移动磁盘，**硬过滤系统盘与数据盘**（只列 USB  removable 设备）；只有 1 个候选时仍需用户确认一次（防误写唯一确认点）
3. **容量检查**：<64GB 提示换盘
4. **组件下载**：按服务器 `manifest.json` 下载——Ventoy 包、AI-Repair-Live.iso、WinPE、MemTest86+（以上为本项目自产/开源组件，托管于 CDN）；**Win10/Win11 ISO 采用 Fido 式官方链接动态解析**（安装器运行时实时向微软服务器请求授权下载链接，实际文件始终从微软服务器下载，本项目不分发微软任何字节——与 §2.4-4 合规条款一致；此路径经 Rufus/Fido 多年大规模验证，同时规避微软直链 ~24h 过期问题）。Win ISO 用户可选跳过以节省时间，默认全选推荐。下载用 **BITS（Windows）/ curl 断点续传（Linux）** + SHA256 校验，不自研分块并行（BITS + CDN 已够）
5. **写入**：调用 Ventoy CLI（`Ventoy2Disk.sh` / `Ventoy2Disk.exe -CMD` 无人值守模式）安装引导层 → 挂载数据分区 → 拷入 ISO + ventoy.json + /config 骨架
6. **校验**：重读分区结构 + 逐文件 SHA256 核对
7. **完成**：中文提示 + 可选弹出 U盘

### 2.5.4 服务器端

- 纯静态托管即可：`manifest.json`（组件清单：版本/URL/大小/SHA256）+ 自产组件文件（Ventoy 包、AI-Repair-Live.iso、WinPE、MemTest86+）
- **故障隔离（V1.4 新增）**：manifest 与组件托管到**独立 CDN 域名**（与 API 网关 tokeneff.com 不同域），制作服务与 AI 网关互不单点牵连
- manifest 版本化：安装器启动时拉取最新 manifest，**组件升级 = 改 manifest，无需改安装器**
- 网页本身：单页静态页，显示命令 + 复制按钮 + 图文 FAQ（含 UAC/杀软提示说明、毁盘警告）

### 2.5.5 安全设计（V1.4 加固）

- 下载全程 HTTPS + SHA256 校验，防篡改
- 写盘前二次确认 + removable 设备硬过滤（双保险）
- **供应链防护**：① 安装器版本化 URL（`/usb-v1.2.ps1`），不在同一 URL 下静默换内容；② 网页公布脚本 SHA256 与变更日志；③ 脚本首行嵌入版本号，执行时先输出版本供核对；④ 向维修人员用户提供「先下载审阅再执行」的两段式替代命令（`irm -OutFile usb.ps1` → 审阅 → 执行）
- 脚本明文可审（PowerShell/shell 纯文本），网页附「这个命令做了什么」白话说明

## 2.6 选择式交互体系（V1.3 新增）

**原则：能选不聊；能替用户选的自动选最优并标注「推荐」；每步最多一次确认。**

### 2.6.1 启动后主菜单（whiptail 中文图形化菜单，非纯文本对话）

```
┌──────────── AI 电脑维修助手 ────────────┐
│  请选一个任务（↑↓ 选择，回车确认）：      │
│                                         │
│  ❯ 1. 电脑体检（自动全面检测，推荐新手）  │
│    2. 重装系统（自动推荐最优方案）        │
│    3. 忘记开机密码                      │
│    4. 备份/抢救文件                     │
│    5. 硬件检测（硬盘/内存/温度）          │
│    6. 自由对话（直接说出您的问题）        │
└─────────────────────────────────────────┘
```

- 菜单项 1-5 为**固化流程**：进入后由 Claude Code 接管，但所有提问一律以编号选项形式给出
- 菜单项 6 为兜底自由对话

### 2.6.2 交互准则（V1.4 修订：确定性行为归脚本，对话风格归提示词）

**分工原则（critic 审计确立）**：确定性行为——选项编号、确认次数、进度条、每屏行数——**由脚本和 whiptail 承担**（代码保证 100%）；CLAUDE.md 系统提示词只负责**引导** Claude Code 的对话风格（提示词约束是概率性的，不能"强制"终端行为）。

脚本层硬保证：
1. 固化流程（菜单 1-5）的所有交互均为 whiptail 编号选项，标注「推荐」项，默认回车 = 推荐项
2. 危险操作合并为一次确认：把「将做什么 + 影响什么」一屏讲清，用户回车确认
3. 每屏信息 ≤ 7 行：结论先行，细节折叠为「输入 s 查看详情」
4. 长任务显示进度条/百分比，不让用户面对静止屏幕

CLAUDE.md 引导的对话风格（自由对话及流程内解说）：
5. 全程大白话：禁用术语；必须出现时附一句白话解释（如「ESP 分区（系统启动用的小分区）」）
6. 对话中需要用户决策时，优先使用编号选项形式并给出推荐

### 2.6.3 自动最优决策表（示例）

| 场景 | 自动决策逻辑 |
|------|------------|
| 镜像版本推荐 | CPU 支持 TPM2.0 + 内存 ≥8GB → Win11 24H2（推荐）；否则 Win10 22H2 |
| 分区方案 | 单盘单系统 → EFI 100M + 全盘主分区（推荐）；检测到数据分区 → 提示保留 |
| 网络方式 | 有线已插 → 静默直连不打扰；仅有无线 → 直接列出 WiFi 列表让选 |
| 体检流程 | 一键全检：CPU/内存/硬盘 SMART/温度/系统盘健康，直接出中文报告与处理建议 |
| 密码重置 | 自动枚举 Windows 用户列表 → 编号选择要重置的账户 |

### 2.6.4 降级一致性

离线模式（网关不通）下同样呈现选择式菜单（whiptail），保持「能选不聊」原则在无网时也成立。

### 2.6.5 菜单 → Claude Code 交接机制（V1.4 新增）

菜单脚本以**初始 prompt 参数**启动 claude，把用户选择传入对话上下文：

```bash
# /usr/local/share/tasks/ 下的任务描述文本文件化，与 CLAUDE.md 一起版本管理
case "$choice" in
  1) exec claude "$(cat /usr/local/share/tasks/tijian.txt)" ;;    # 电脑体检
  2) exec claude "$(cat /usr/local/share/tasks/reinstall.txt)" ;; # 重装系统
  3) exec claude "$(cat /usr/local/share/tasks/password.txt)" ;;  # 密码重置
  # ...
  6) exec claude ;;  # 自由对话
esac
```

任务文本约定 Claude Code 调用的脚本入口（如体检 → `disk-check.sh` 等），Claude 负责解说与异常分支处理，脚本负责确定性执行——与 §2.6.2 分工原则一致。**任务文本首行统一加前缀**「（系统流程，请直接开始执行，不要复述任务）」，避免 claude 把任务描述当闲聊回应（P3.5 实测验证）。

## 3. 关键风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| **网关可用性依赖（新增）** | tokeneff.com 不可达时 AI 功能全部失效 | 进入 Claude Code 前强制连通性检查；不通则降级本地诊断菜单；网关侧需 SLA 保障（超出本方案范围，列为外部依赖） |
| 网卡驱动不识别（冷僻硬件） | 无法联网 = AI 失效 | 全套固件 + USB 网卡兜底 + 手机 USB 共享网络；附件清单建议随盘附 RTL8153 USB 网卡 |
| 维修现场无网络 | AI 功能失效 | 离线降级菜单 + 本地脚本工具集 |
| Secure Boot MOK 登记摩擦（严重度上调，critic 发现 #12） | 家庭用户首次启动卡在蓝屏 MOK 界面 | 说明书配逐步图文指引（ enroll MOK → 输入密码 → reboot）；量产阶段验证主流品牌机表现 |
| BitLocker 加密分区（critic 发现 #3） | 密码重置/数据备份场景失效 | dislocker 集成 + SOP 解锁分支 + 恢复密钥获取指引 |
| Intel VMD 新机看不到硬盘（critic 发现 #4） | 装机员场景失败 | DISM 预注入 RST 驱动 + BIOS 关 VMD 备选 |
| 中文输入到 Claude Code TUI 兼容性 | 核心体验单点故障 | **提前至 P0.5 Spike 验证**（见 §4），不通过则切换备选终端/输入法组合（见 §5-4） |
| 误操作毁数据 | 重大事故 | 三层防护：CLAUDE.md 约束 + 脚本二次确认 + by-id 设备白名单校验 |
| **Fido 动态解析失效（新增）** | 微软改下载页结构 → 一键制作无法获取 Win ISO | 安装器内置解析版本自检（与 manifest 版本绑定）；网页公告 + 手动从微软官网下载拷入兜底；解析逻辑参考 Fido 自研或调用原版（GPL-3.0，调用原版需注明出处，不内嵌其代码） |
| exFAT 分区长期插拔损坏（critic 开放问题） | U 盘数据区损坏 | 说明书指导安全弹出；提供 `exfatprogs` fsck 修复指引 |
| Claude Code 在低内存（<4GB）老机器流畅度 | 体验差 | P5 真机测试覆盖低配置机型；必要时提供纯字符界面（不启动 Xfce，用 fbterm+fcitx）备选启动项 |
