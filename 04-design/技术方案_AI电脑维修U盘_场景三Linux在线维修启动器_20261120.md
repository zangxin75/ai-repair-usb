# 技术方案：场景③ Linux 在线维修启动器（repair-on-linux.sh）

- **创建日期**: 2026-11-20
- **版本**: V1.0
- **状态**: 定稿（critic 三轮审计 6.5 REVISE → 7.5 REVISE → **8.5 ACCEPT**，2026-11-20）
- **作者**: Claude Code + kt

## 0. 背景与范围

场景③（已进桌面的在线维修）现有 Windows 端启动器 `repair-on-windows.ps1`（v0.5.6）。本方案新增 **Linux 端**：U盘插到正在运行的 Linux 桌面系统，在终端内直接运行启动器完成在线维修/办公/编码。

**用户已拍板的两个决策**：
1. **精简版**：只做 Claude 引擎（U盘 bin/ 现有便携组件 claude.exe/node.exe/codex.exe/OpenClaw/Pi 均为 win32 二进制，Linux 不能执行）；Pi/OpenClaw/Codex 入口不做。
2. **引擎获取「便携优先 + 在线兜底」**：Linux 制作器（usb-v1.0.sh）额外落盘 `bin/claude-linux`；启动器拷到本机临时目录执行；缺失时回落链 = 本机已装 claude → 在线官方 GCS 桶 linux-x64。Windows/Web 制作器不改（其盘走回落链，已知代价）。

**v0.1 明确排除**：启动器自更新（过渡通道：Ventoy `-u` 无损升级重跑投放段即刷新；将来自更新用 manifest `launcher-linux` 平行字段，不破坏 ps1 单对象 launcher 解析）、udev 插盘自动弹出、多 Agent、ps1/Web 制作器的 linux-x64 投放、enterprise 模式会话历史保留的完整实现。

## 1. 临时目录与提权安全

- 所有临时目录一律 `WORK="$(mktemp -d "${TMPDIR:-/tmp}/ai-repair.XXXXXX")"` + `chmod 700`；绝无固定路径（共享 /tmp 固定路径 + root 执行 = 本地提权通道，第一轮 BLOCKER）。
- 低权进程与 sudo 重入进程**各自 mktemp 各自 trap 清理**，互不复用、互不传递路径。
- 脚本开头 `SCRIPT_PATH="$(readlink -f "$0")"` 归一化并全程使用绝对路径（免疫内部 `cd`）。
- 维修会话提权：子进程 `sudo bash "$SCRIPT_PATH" --repair`（显式 bash，消除 exFAT x 位/noexec 对 execve 的依赖；**不用 exec**——exec 会丢弃 trap 导致含 key 的临时文件残留，且降级分支不可达）：
  - sudo rc≠0（无 sudo 二进制 / 不在 sudoers / 密码取消或输入失败，含 requiretty/二次认证失败）→ **降级为只读诊断会话**（镜像 ps1 拒绝 UAC 不退出语义）；
  - rc=0（root 侧维修会话正常结束、其 trap 已自清）→ 低权进程打印结束文案后正常退出，触发自己的 trap 清理。
- `--repair` 重入进程：校验 `[ "$(id -u)" -eq 0 ]`（非 root 带 --repair 拒绝退出）；重读 config/auth_token（无则重走激活）+ 重查余额后**直进维修会话**；**会话结束即退出整个脚本**（不回菜单）。
- 整脚本被刻意以 root 启动（无 --repair）时：[2] 可直进维修会话，**[3]/[4] 拒绝并提示在普通权限下使用**（杜绝 root + `--dangerously-skip-permissions` 组合——该组合在 Windows 版不存在）。
- /tmp noexec 兜底：便携二进制拷入 `$WORK` 后先试执行（`--version`），失败则换 `mktemp -d "$base/ai-repair-work.XXXXXX"`（700）重拷执行；低权侧 `base=${XDG_DATA_HOME:-$HOME/.local/share}`，**root 侧 base 显式 `/root/.local/share`（mkdir -p，不依赖 $HOME 与 sudoers env_keep 解析，root 进程不写调用者家目录）**。
- trap 写法：`trap cleanup EXIT` + `trap 'cleanup; exit 130' INT TERM`；cleanup 幂等（rm -rf 对不存在路径无害、unset 幂等，防信号+EXIT 双触发重复执行出错）。

## 2. 定位与配置

- 以脚本自身路径定位U盘根 + `config/settings.conf`（与 ps1 R5/R6 同语义；找不到即 die，防复制到本地运行）。
- settings.conf 解析规则同方案 5.1：KEY=VALUE、整行注释、KEY 两侧空格警告容忍；必需项 ACTIVATE_URL / BALANCE_URL 缺失即 die。
- CONFIG_OVERRIDE=1 为历史无消费者字段（保留原样兼容存量盘）。

## 3. 网关封装（对等 ps1 0.5.6）

- `gw_curl METHOD URL [JSON]`：`curl -sS -o "$WORK/gw-body.json" -w '%{http_code}' --max-time 30`，请求头 `X-Requested-With: XMLHttpRequest`（portal CSRF）+ `Authorization: Bearer $KEY`（POST 另带 Content-Type）；**不用 -f**（4xx 响应体必须保留供 detail 透出）。
- **只有 curl 退出码非 0（网络层错误/超时）才重试**，间隔 5s/10s 共 3 次；HTTP 状态码（含 429/403/5xx）一律不重试、交分支处理（对 429 重试会加剧 IP 限频）。
- 403 分支 detail 透出：body 首字符为 `{` 则提取 detail 字段输出（对齐 Get-GatewayErrorDetail）。
- 凭证失效：余额查询 401/403 → 提示删除 config/auth_token 重新激活。
- 409（key 过期 12 个月）：显示U盘根 upgrade-url.txt 升级入口（缺省回落 https://tokeneff.com），引导付费/续费。
- 网络重试耗尽 → 场景②离线维修引导文案后退出。
- JSON 解析三层（字段集合固定：key / batch_id / remaining_weekly / total_used_monthly / expires_at / verification_required / already_verified / detail）：**jq → python3 → 纯 sed/grep**；sed 层含字符串 `"f": "v"`、数字 `"f": 123`、布尔 `"f": true` 三种模式——双缺 jq/python3 的客户机仍可跑通全流程（余额数值闸门可用）。如实接受：403 detail 值含 `\"` 转义时 sed 截断，仅影响显示不影响分支路由。

## 4. 激活与凭证契约（对等 ps1 全量）

- 请求体：usb_sn + machine_fp + maker_version（读U盘根 maker_version，缺省 unknown）+ 可选 promo_code（settings.conf PROMO_CODE 作默认值，终端可覆盖/回车跳过——20% 分成入口）。JSON 值做反斜杠/引号转义。
- U盘序列号：`udevadm info --query=property --name <挂载源设备>` 取 ID_SERIAL_SHORT（`lsblk -dn -o SERIAL` 兜底；均缺 → UNKNOWN 不阻断）。
- **机器指纹如实降级**：dmidecode 与 `/sys/class/dmi/id/board_serial` 非 root 均 0400 不可读，而激活发生在低权进程 → **Linux v0.1 machine_fp 恒 UNKNOWN**（指纹仅观察字段不阻断；召回功能 Linux 侧降级，双处声明）。
- 200：写 config/auth_token（无 BOM UTF-8 + 末尾换行；umask 077 + chmod 600 尽力而为，exFAT 无权限位时容忍）；**batch_id 幂等写回 settings.conf**（有 BATCH_ID= 行则替换、无则追加；sed -i 同卷 tmp+rename 原子替换）。
- 分支文案 429（每 IP 每日限量）/ 403（透 detail）/ 423（风控暂停）/ 409（过期+升级入口）/ default（网关不可用→场景②引导）与 ps1 逐字对齐。
- **agents.json 闸门**：`claude.userDeclined=true` → 引擎链只允许U盘 bin/claude-linux 级，禁止本机/在线两级，提示「重跑制作命令可补装」（对齐 ps1:679-683）；文件缺失 = 存量盘兼容按已装处理。

## 5. 模式菜单与引擎获取链

一级菜单（每项带全名，防 ps1 用户肌肉记忆误点）：

```
[1] 只读诊断（免提权，收集信息+建议）
[2] 维修会话（需管理员权限 root）
[3] 办公助手（写文档/表格/文案，免提权）
[4] 编码模式（软件开发/脚本，完全控制权限，免提权）
[5] 余额查询 / 管理账号（含邮箱验证入口）
[0] 退出（清理本机临时文件）
```

- 额度闸门对齐 ps1：exhausted（remaining ≤ 0）拦截 [2][3][4]；lowBalance（< 2,000,000）仅提醒 + 升级入口。
- 邮箱验证：verification_required=true → 输邮箱 → POST /verify（already_verified 直接过；429 提示 60s 冷却/每日 5 封）→ 输码 → POST /verify/confirm（失败提示重试路径）；未完成仅警告不阻断（R23）。
- 引擎链（会话启动时解析）：
  1. U盘 `bin/claude-linux` + **`bin/claude-linux.sha256` 旁车强校验**（旁车缺失回落 >100MB 尺寸判据，对齐 ps1 便携判据）→ 拷入 $WORK chmod +x → 试执行（noexec 走 §1 兜底）；
  2. 本机 `command -v claude`；
  3. 在线：GCS stable → 版本 manifest 取 **linux-x64** checksum（sed 范围模式块内匹配，**已实测**：stable=2.1.311，linux-x64 为裸 ELF `claude` ~294MB，`{base}/{ver}/linux-x64/claude`）→ 下载后 sha256 校验 → 落 $WORK。三级全失败 → 场景②引导 + 常见原因中文诊断。
  - ①③ 受 agents.json 闸门管控；②③ 被闸门禁用时仅①可用。
  - GCS 直连维持现状口径：制作器现有 win32 下载即同依赖（国内制作需自备可达 GCS 的网络），不引入 gh-proxy 类反代（避免「第三方转发官方字节」红线争议）；运行时在线下载失败落场景②兜底。

## 6. 会话环境（沿用 0.5.6 排雷结论）

- `ANTHROPIC_BASE_URL`：settings.conf GATEWAY_BASE_URL 非空则覆盖，缺省 https://tokeneff.com。
- `ANTHROPIC_AUTH_TOKEN=$KEY`（仅本进程环境，不落盘）；**unset ANTHROPIC_API_KEY / ANTHROPIC_OAUTH_TOKEN**（双凭证残留排雷）；**ANTHROPIC_MODEL=claude-sonnet-5 且 ANTHROPIC_SMALL_FAST_MODEL=claude-sonnet-5 双钉死**；**unset ANTHROPIC_DEFAULT_MODEL**（残留模型名撞白名单 → 402/403 误报排雷）。
- `DISABLE_AUTOUPDATER=1` + `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` 覆盖全部三级引擎来源（在线下载进 $WORK 的二进制同为便携性质跑完即删）。
- `CLAUDE_CONFIG_DIR=$WORK/claude-config`：从 config/claude-config/ 复制（缺则空目录）+ config/claude-skills/* → skills/（缺则无技能模式）；不写 ~/.claude、~/.local（零残留红线）。
- 系统提示词：U盘根 CLAUDE.md → config/claude-config/CLAUDE.md，命中则 `--system-prompt`；**如实标注：现役盘两源皆不存在，实际裸启动**（与 Windows 版同处境，不新增服务器发布依赖）。办公人格 config/office/CLAUDE.md 与只读约束均用 `--append-system-prompt`。编码模式 `--dangerously-skip-permissions`。

## 7. 清理语义

- 两级进程各自 trap，只删自己的目录（含 noexec 兜底目录）+ unset 环境变量；cleanup 幂等。
- RECORD_MODE=enterprise 的盘：[0] 退出时提示「企业运维模式的会话历史保留功能 Linux v0.1 未实现，本次会话历史将随清理删除」，y 确认后清理、否则保留并打印路径；异常退出（Ctrl-C 等）默认保留不静默删。customer（缺省）无痕清理。

## 8. usb-v1.0.sh 制作器改动

1. **linux-x64 下载段**（与 win32-x64 claude.exe 段并列）：GCS stable → manifest 取 linux-x64 checksum → sha256 校验 → 缓存命中检查 → 失败不阻断，文案明示「Linux 便携引擎缺失，Linux 在线维修将依赖客户机网络下载」。
2. **checksum 提取修复（顺手，活 bug）**：官方 manifest 为多行 pretty-print，现有 win32 sed 模式（要求 `"win32-x64"` 与 `"checksum"` 同行）实测匹配为空 → 便携 claude.exe 一直被静默跳过；flatten+贪婪匹配实测错配 win32-arm64。两端统一改 **sed 范围模式**（`/"linux-x64":/,/}/` 块内取 checksum，实测正确）。
3. **落盘**：bin/claude-linux + 写 bin/claude-linux.sha256 旁车 + 盘上 sha256 复核段（对齐 claude.exe 复核模式）。
4. **投放段**：repair-on-linux.sh 加入 maker 服务器投放列表（交付清单含「发布到 usb.tokeneff.com/maker/」步骤）。
5. **写 `$MNT/maker_version`**（printf 脚本版本；使 Win/Linux 两端归因字段同时生效）。
6. 制作完成提示补一行：「电脑还能进 Linux 时: 打开终端 cd 到U盘后运行 bash repair-on-linux.sh 即可在线维修」。

## 9. 测试方案（挂 tests/ 惯例）

三层（`05-tools/tests/repair-on-linux-smoke.sh`，mock curl 沿用 smoke.sh shim 模式）：
- **静态**：bash -n + shellcheck（两个改动脚本）。
- **mock HTTP**：激活五分支（200 含 key+batch_id / 429 / 403+detail / 423 / 409）+ 401 凭证失效 + 余额三字段 + exhausted/lowBalance 闸门 + 邮箱验证两步（verify→confirm、already_verified、429 冷却）；断言 batch_id 幂等写回与 auth_token 内容。
- **环境矩阵**：TMPDIR 未设可运行、同机两次运行 $WORK 路径不同、fake sudo 失败（rc≠0 → 降级只读断言）、无 jq/python3 走 sed 层跑通、--repair 非 root 拒绝、root 会话结束即退出（不回菜单）断言、sudo 成功路径结束后 /tmp 无 ai-repair.* 残留。

真机验收（实机 Linux 桌面发行版 + 真实网关）由用户执行。

## 10. 审计轨迹（critic 三轮）

| 轮次 | 结论 | 要点 |
