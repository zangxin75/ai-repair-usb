## 0. 目标与衡量

| 项 | 内容 |
|---|---|
| 一句话定位 | 一根 U盘 = AI 修电脑 + 免安装 AI 工作站（开源圈独占生态位：微PE/FirPE 无 AI，AI CLI 无「插上就用」形态） |

**时点选择**：攒到 v0.4（P-B 四引擎落地）再转 public，避免首因效应浪费在半成品上。P-B 期间可先并行做 §2~§4 全部离线准备工作。

## 1. 安全与合规门槛（转 public 的硬前置，不过审不得公开）

1. **敏感信息出仓**：`grep -rE` 全仓扫描并移除——服务器 IP（<内部IP> / <内部IP> 等）、SSH 别名（<构建机>）、Tailscale IP、PG/LiteLLM 凭证、一次性 PAT 片段、测试 key。移入 `docs-internal/`（进 `.gitignore`）或独立私有仓。
   - 注意：git **历史**也要查（`git log -p | grep`），有泄漏则需 `git filter-repo` 重写后再公开。
2. **托管服务口径**：`usb.tokeneff.com` 保留，但 README 改为「官方托管网关（免费额度）**或**自建/自购 key 两种用法」，附自建教程（自建教程本身是引流钩子）。
3. **一键脚本免责**：`irm | iex` 等于远程代码执行背书——README 显眼位置加免责声明 + 提供可审计静态脚本直链（`curl -sLO` + 审阅后执行）。
4. **Windows 镜像合规口径统一**：全仓表述统一为「Fido 式动态解析微软官方直链，本项目不分发微软任何字节」（现状已守住，公开后必被审查）。
5. **免费额度防薅**：开源版默认不带额度；额度走 portal 注册制（现状即如此，README 明示，避免公开后免费额度被批量薅——必要时网关侧限速）。

## 2. 门面改造（README 优先级最高）

1. **README 重写**（双语，英文为主、`README.zh-CN.md` 互链）：
   - 首屏：三连 GIF/截图（坏电脑→中文 AI 维修菜单 / 好电脑→双击 AI-Workstation / Codex 开箱即用）+ slogan + 徽章（License / Release / English）
   - 对比表：vs 微PE / vs Ventoy 裸盘 / vs 手动装 Claude Code——突出「插上就用」「中文」「零残留」
   - Quick Start 一行命令 + 「无网关模式」（换任意 Anthropic 兼容 base_url 用自己的 key）
   - Roadmap：P0~P8 转公开里程碑；Contributing 指南
2. **Social Preview 图**：1280×640 概念图（U盘 + AI 徽章视觉），分享卡片主视觉。
3. **仓库名与 topics**：候选更名 `usb-doctor` / `ai-rescue-stick`（旧名 redirect 保留）；topics：`ai-tools` `claude-code` `ventoy` `rescue-usb` `windows-repair` `live-iso` `debian`。
4. **Release 化**：GitHub Releases 挂 ISO 与 sha256（>2GB 单文件用分卷或 Release asset 直传），tag 规范 `v0.4.0`；Release notes 写真实踩坑故事（四轮构建排雷、402 三层定位——过程叙事是最好的传播素材）。
5. **FUNDING.yml / ISSUE_TEMPLATE / Discussion 区**开启：降低参与门槛， star 之外的互动入口。

## 3. 一键复现路径（开源信任基石）

1. `build.sh --all`：构建机准备→ISO 产出→sha256 的单命令复现文档，以「陌生人视角」重写（现有构建链已具备，缺的是不自证视角的说明）。
2. 「自建网关」教程：任意 Anthropic 兼容网关（LiteLLM/oneapi 等）对接本盘的配置说明——吸引 selfhosted 社区。
3. `tests/smoke.sh` 在 README 展示为「无硬件冒烟 15/15」，给潜在贡献者一个 5 分钟上手路径。
4. CI（GitHub Actions）：`bash -n` + shellcheck + smoke 的免硬件流水线，PR 即验证（ attract 贡献的信任设施）。

## 4. 发布节奏与渠道（三板斧）

1. **首发**：v0.4 转公开当天——Show HN（英）+ V2EX 分享创造节点 + 少数派投稿。
2. **过程内容营销**：排雷实录译英文发 dev.to/Medium，每篇回链仓库（标题候选：「我用 live-build 做了根 AI 修电脑 U盘，踩了 4 轮坑」）。
3. **长尾**：B 站/YouTube 3 分钟演示视频挂 README 头部；微PE/FirPE 相关贴吧知乎问题下克制回答引流。

## 6. 风险表

| 风险 | 等级 | 缓解 |
|---|---|---|
| 历史提交含凭证 | 高 | S1 `git log -p` 全量审查；有则 filter-repo 重写 + 全部凭证轮换后再公开 |
| 一键脚本被指供应链风险 | 中 | 免责声明 + 静态可审计下载路径 + sha256 |
| 免费额度被薅 | 中 | 默认无额度、注册制、网关限速开关 |
| 微软镜像合规质疑 | 中 | 口径统一（§1.4），发布物零微软字节 |
| 更名丢星/丢链 | 低 | 旧仓 redirect；首发前定名 |
| issue 洪峰维护压力 | 低 | ISSUE_TEMPLATE + Discussion 分流 + Roadmap 明示范围 |

## 7. 验收判据（S5 出口）

- [ ] 陌生人 clone 后按文档 30 分钟内完成一次构建或一次 U盘 制作
- [ ] Release 资产 sha256 双端一致；CI 绿
- [ ] 首发 3 帖（HN/V2EX/少数派）文案过审（无夸大、有免责）
